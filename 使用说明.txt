UC 多线程下载器 — 使用说明
================================

作用
----
UC 网页下载是按“单个连接”限速的（实测约 0.5 MB/s，1.58GB 要下近一小时）。
本工具用 64 个连接同时拉同一个文件的不同片段，实测同一文件 58 秒下完（约 27 MB/s），
并支持断点续传、自动重试、大小与空洞校验。


三步使用
--------
1) 在 UC 网页点「下载」，让浏览器先开始下载（这一步只是为了生成临时直链，可随时取消）

2) 浏览器按 F12 → 切到 Network（网络）面板 → 找到那条 mp4 请求
   （名字像一串 40 位十六进制、Type 显示 document）
   → 右键该请求 → Copy → Copy as cURL (bash)

3) 打开本程序，把整段内容粘进输入框 → 点「解析并开始下载」
   · 程序启动时会自动读剪贴板，如果里面已经是 curl 内容会自动填好
   · 也可以点「从剪贴板粘贴」
   · 下完点「打开所在文件夹」，文件默认保存在 用户目录\Downloads


必须由每个人自己提供的东西（不能共用）
--------------------------------------
1. 自己的 UC 登录状态（Cookie）——整段 cURL 里就带着它，程序自动解析
2. 自己那份文件的临时直链——有效期约 3 小时，过期要回网页重新复制

安全提醒：
  Cookie 等于账号登录态，拿到就能进你的网盘。
  · 不要把带 Cookie 的内容发给别人、不要贴到网上
  · 给别人用的时候，对方必须登录自己的 UC 账号、自己 Copy as cURL
  · 本程序只把这些信息用于向 UC/阿里云 OSS 请求文件本身，不做任何上传


参数说明
--------
· 连接数：默认 64。实测 4→1.9、8→3.8、16→7.5、32→15、64→27 MB/s（线性）
          96 反而略降到 25.8，所以 64 通常是甜点值；跑不满就加，加不上去说明卡在宽带
· 分块大小：默认 4 MB。网络抖动大可以降到 2 MB（重试代价小），追求快可以升 8 MB
· 进度条、瞬时/平均速度、已完成块数、预计剩余时间都在窗口里显示，标题栏也会同步


常见问题
--------
· 报 “403 require login [auth not found]”
  → 没按要求用 Copy as cURL（只粘了链接），或 Cookie 已失效。按三步重来一次。
· 报 “403 直链已过期”
  → 直链有效期约 3 小时。回网页重新点下载、重新 Copy 粘贴即可，
    程序会自动发现上次进度并继续续传，不用从头下。
· 进度条开头几秒增幅偏小
  → 正常。速度是按“已接收字节”实时统计的，开头建立连接时偏低，稳定后会拉起来。
· 中途停止 / 关掉程序
  → 已下部分保留在同名文件的 .parts.json 里，下次粘新直链点开始就接着下。
· 完成时的自检
  → 日志会显示「大小校验通过」和「空洞检查：全零块 0 个（正常）」。
    想更严格可以用 ffprobe / 播放器直接试播。
· 杀毒软件报毒 / 提示未知发布者
  → 这类单文件小工具常被杀软误报，加信任即可；不放心可以直接跑源码 uc_gui.py
    （只用 Python 标准库 tkinter，无第三方依赖）。
· 打不开、闪退
  → 同目录会生成 crash.log，把内容发回来即可定位。


给开发者 / 想改的人
------------------
· uc_gui.py   图形界面版源码
· download.py 命令行版（读同目录 url.txt / cookie.txt，适合脚本化）

已知限制
--------
· 依赖 UC 现有的回调鉴权机制，UC 改规则时本工具可能失效，需要跟着更新
· 不能只靠“分享页链接”自动取直链，那需要内嵌浏览器扫码登录，属于另一个量级的工程
